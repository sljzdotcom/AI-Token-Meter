# v0.10.7 Antigravity 恢复修复发布计划

**需求：** REQ-20261007-001  
**目标：** 将 Antigravity 一次性受控恢复修复作为 v0.10.7/build35 稳定版本发布到 macOS 与 Windows 更新通道。  
**发布基线：** 公开 main `ddeec3b`（v0.10.6）；本机已完成实现 `a2de0f3`、开发记录 `d20670c`、验证记录修订 `f8fa5a2`。  
**范围边界：** 只发布一次性恢复产品代码、对应测试、设计/实现/发布文档和版本元数据；不纳入隔离原型工具或原型实验文档，不安装应用、不登录真实账号、不运行真实 `agy`、不改 M4 Max 现场暂停。

## 发布步骤

1. 在唯一需求台账登记授权和 v0.10.7/build35 发布事务；保留 REQ-20261001-002 的现场恢复待确认状态。
2. 从最新 `origin/main` 创建发布候选分支；选择性纳入一次性恢复的 macOS 源码、测试和必要产品文档，排除 `tools/antigravity-isolation-prototype` 与该实验的专属文档。更新根版本、macOS App/Widget、Windows npm/Cargo/Tauri 元数据到 0.10.7/build35；维护 CHANGELOG、README、Release Notes 和本计划/开发记录索引。
3. 运行完整 `scripts/test.sh`、Windows 前端/密度构建与 Rust 合同、本机 Release 包/签名安全检查、跨平台合同、文档与公开内容扫描。最终代码已有 635 项 Swift（Core 299、App 324、Widget 12）、107 suites 通过，21 项宿主/设备条件测试按设计跳过；版本改动后仍重新运行发布门禁。
4. 对候选精确 diff 进行独立只读审查，修复所有 Critical/Important 项。创建针对 `main` 的 PR，并等待 macOS/Windows 原生 CI 通过。
5. CI 全绿后合并 PR；在合并后的精确 main 头重新核验源码、版本与需求/发布文档，创建并推送 `v0.10.7`，从同一标签启动既有双平台签名发布 workflow。
6. workflow 将公开 macOS Sparkle ZIP、校验文件和 appcast，生成 Windows NSIS 安装器、Tauri 更新签名、校验文件及 `latest.json`；公开稳定资产后只通过既有 workflow 更新根 `appcast.xml`、Windows stable feed 与固定 `windows-preview-feed`。不导出或显示私钥，不新增 Secrets。
7. 以匿名下载重新验证双平台资产、SHA-256、macOS Sparkle EdDSA、Windows minisign 更新签名及篡改拒绝；检查三个 feed 均指向本版本并与 Release 字节一致。发布后补全本计划、开发记录索引及唯一需求台账，并回传安装/现场验收边界。

## 当前验证基线与停止条件

- 当前发布版本为 v0.10.6/build34；远端未发现 `v0.10.7` 标签。
- 候选只从最新 main 生成。远端 main 更新时先检查差异，不重置、不强推；版本、tag 或 feed 若已被其他事务占用则停下并保留现有资产。
- 如发布工作流或审批阻止公开操作，保留分支、PR/草稿与已公开资产的安全状态，回传具体阻塞；不绕过审批，也不声称 M4 Max 额度恢复。
