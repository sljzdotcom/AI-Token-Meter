# Antigravity 单次受控恢复规格

**需求：** REQ-20261001-002  
**基线：** v0.10.6 / build34 / `0823e07`，本地原型证据提交 `f289978`、`0c8cdf7`
**状态：** 用户已批准本地产品修复；不发布、不运行真实 `agy` 或登录、不操作账号、现场暂停或已安装应用。

## 目标

对持久暂停的 Antigravity 提供明确的一次性恢复入口。unknown 历史暂停与认证暂停都可由用户主动启动；官方 CLI 登录成功后只允许一次有界额度读取。失败、取消、窗口关闭、超时、过期/伪造回调、脚本错误或应用退出都不能解除暂停或触发额度读取。一次性额度成功后保留新的额度缓存，但自动刷新继续暂停，应用重启后也不能自动恢复。

## 用户界面与授权边界

- Services 与 Antigravity 详情在持久暂停时显示同一个“一次性检查额度…”入口；显示条件不依赖旧暂停原因是否为 `authenticationRequired`。非暂停状态沿用现有 Retry 和采集行为。
- 点击前向用户说明将打开官方 Antigravity CLI 的 Terminal 登录流程，可能打开浏览器或出现授权页；本功能不提供 OS 级阻止其他应用启动的保证。一次合法登录回执只会触发一次额度检查；自动刷新仍保持暂停。
- 登录中提供有限等待期和取消/到期说明。进度、失败与成功状态都明确显示暂停仍有效；成功文案为“单次检查成功，自动刷新仍暂停”。
- 本轮只修改 macOS 应用 UI 与 Swift 采集核心。Windows Rust 实现不添加登录/恢复入口或认证方式；共享 JSON 与额度模型不改变。

## 状态机

应用内的一次性恢复是短生命周期、不可恢复的状态：

`idle → awaitingLogin(token, deadline) → checkingQuota(token) → succeeded | failed`

- 用户点击时，应用先检查暂停状态、单次操作未占用且正式应用允许外部打开，然后创建不可预测 UUID token，并通过专用登录脚本打开官方 `agy`。打开失败立即结束为失败，原持久暂停不变。
- 登录脚本为本次操作建立独立进程组并启动 `agy`，用 300 秒看门狗只终止本进程组；UUID 只保存在内存并经 0600 命名管道送入自删除脚本，不写进脚本文件。脚本会等待整个自有进程组退出，若主 CLI 退出但留下子进程，看门狗仍会按期限清理。只有退出码为 0 才回送 `result=success&exit_code=0`；非零退出回送失败结果。脚本收到关闭/中断信号时只清理自身进程组并回送非成功结果；若终端被直接关闭导致回执丢失，应用 330 秒到期任务终止等待。登录脚本和界面明确可能出现浏览器授权页，不尝试代理、重放或拦截 OAuth。
- 回调必须匹配当前尚未过期的 token，且只有 `result=success` 配合退出码 0 可原子地把 `awaitingLogin` 迁移为 `checkingQuota`。失败回执、错误 scheme、缺少/非法参数、重复、过期、未知 token 或已退出应用后的回调均拒绝，不运行采集。
- 在 `checkingQuota` 状态时拒绝第二次回调、按钮重入及并发恢复。额度采集结束后 token 作废，回调不能再使用。AppModel 停止时清除所有临时 token 并取消等待/采集任务；应用启动不会从磁盘恢复此状态。持久暂停一直由原有 `suspended` 退避记录保护。

## 一次性采集与持久化

- 成功登录回执使用独立 quota-only collector 路径，不调用全局 `AppModel.refresh()`，也不调用任何清暂停 API。该路径最多运行 `agy --version`（8 秒上限）与 `agy -p /usage --print-timeout 20s`（30 秒进程上限）；解析必须返回非空、合法额度数据才算成功。其余耗时上限由命令 runner 和 AppModel 的回执 deadline 约束。
- 恢复路径不运行 `/model`、`models` 或其他 Provider 的命令。正常 Gemini collector 与其他 Provider 的常规路径保持原样。
- coordinator 对此专用采集串行化，并且只在持久暂停时允许调用。成功后原子更新 Gemini 缓存、保留其他 Provider 缓存及 `fetchedAt`；失败/取消/超时不写入新的额度快照，原缓存继续显示为旧数据。
- 成功或失败后均不移除、重置或改写持久 `suspended` 记录及其旧原因。不得以本次登录成功推断额度读取成功；不得用新错误覆盖旧暂停原因来伪造历史。此次实际尝试只向有限诊断环记录白名单阶段、结果类别、时长及时间，不保存命令输出、凭据、账号信息或 OAuth URL。
- 成功提示在当前会话明确说明“单次检查成功，自动刷新仍暂停”；重启后应用继续显示暂停，并通过缓存时间区分上次额度数据。启动、唤醒、定时、普通 Retry、deep link 均无法运行暂停中的 Gemini collector。

## 安全、并发与失败处理

- UUID token 由内存一次性状态持有，通过 0600 FIFO 短暂传递，脚本启动后自删除；不持久化可供重放的授权回执。成功采集及缓存原子提交最多发生一次。
- Shell watchdog 只向本脚本启动的独立 `agy` 进程组发信号，不按进程名杀进程，不操作 Terminal 里的其他会话或浏览器。AppModel deadline 使窗口关闭/无回执最终失效；新启动的应用不接受旧 token。
- 如其他 Provider 的周期刷新在恢复期间发生，只能按现有逻辑刷新那些 Provider；暂停中的 Gemini 仍被过滤。若较早启动的普通刷新在单次额度更新后才结束，磁盘与 AppModel 都保留较新的 Gemini 快照。Gemini 的一次性采集由 coordinator 单独持有，不与定时、唤醒、manual refresh 并发。
- 成功 CLI 退出只是登录流程回执，不等同认证已被额度服务接受。额度命令超时、退出非零、认证失败、输出截断、解析失败、取消、缓存写入失败均显示本次未取得新额度、旧缓存仍旧，自动刷新保持暂停。
- 自动化测试全部使用合成 CLI、临时目录、模拟系统 opener、假 Token 与本地时钟；默认外部操作策略继续 fail closed。不得运行真实 `agy`、打开 Terminal/浏览器、接触 Keychain 或更改现场状态。

## 验收

1. 暂停原因 `unknown`、`authenticationRequired` 与其他已知原因均能从 Services 和 Antigravity 详情发起同一手动流程；提示和状态信息覆盖英文、简体中文、繁体中文。
2. 非零/中断/超时登录、脚本打开错误、窗口关闭无回执、App 退出、坏/重复/过期/未知回调均不清暂停、不执行 quota collector；重复点击和并发定时不会重复启动。
3. 成功回执仅运行版本检查和一次 `/usage`，parser 成功后最多更新一次 Gemini 快照；不运行 model/catalog/其他 Provider 命令。
4. 一次性成功后 `refreshPaused=true` 跨 coordinator/app 重建保持；后续自动、手动和启动刷新都不运行 Gemini collector。失败不覆盖缓存且可明确看出缓存并非新数据。
5. 当前尝试的诊断记录准确标明 login/version/usage 与结果，旧原因/阶段缺失仍为 unknown，日志无原始敏感内容。
6. 正常未暂停 Gemini、其他 Provider、Windows Rust 产品与跨平台额度 JSON 合同不退化。

## 可验证边界

模拟测试可验证回调、超时、PID 生命周期、持久退避、次数与缓存行为，不证明官方 `agy` 在真实账号上的交互行为，不证明系统能阻止该 CLI 启动浏览器，也不验证 M4 Max 现场。此处不声称 OS 隔离；未来的现场操作需使用明确候选版本并另行授权。
