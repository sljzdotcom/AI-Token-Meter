# 产品可见性与摘要同步设计

关联需求：REQ-20260913-002。日期：2026-09-13。

## 问题与根因

Settings 将隐藏产品和产品顺序保存在悬浮条偏好中。悬浮条读取 `visibleProviders`，但 macOS 菜单栏面板及其最高用量摘要直接读取全部快照；Windows 托盘菜单则固定创建四个摘要项。因而同一份设置只影响悬浮条，没有影响两个平台的摘要入口。

## 目标行为

- 悬浮条、macOS 菜单栏面板及 Windows 托盘摘要使用同一份可见产品顺序。
- 修改隐藏或排序设置后，现有界面立即反映新结果；重开应用后结果保持。
- macOS 菜单栏百分比只在可见产品中计算最高用量。
- 恢复产品显示后，其摘要按保存顺序重新出现。
- 隐藏只影响摘要呈现，不删除快照、账户状态、凭据或 Settings 中的服务管理入口。

## 实现

macOS 的 `AppModel` 提供按 `stripPreferences.visibleProviders` 排序过滤的菜单栏快照，菜单栏卡片和最高用量摘要共同读取它。该值由可观察的设置和快照计算，因此已打开面板会随设置更新。

Windows 从 `StripPreferences::visible_providers()` 生成托盘摘要顺序。四个摘要项和六个操作项只在启动时创建一次；快照事件只更新对应摘要文字，设置事件复用现有项调整可见顺序并更新语言，避免后台刷新替换正在显示的原生菜单。菜单事件 ID、账户数据和采集逻辑保持原有合同。

## 验收边界

自动化覆盖任意隐藏、重新显示、重排、偏好重载、摘要最高值和底层快照保留。Windows 原生菜单的实际绘制由 Windows 构建与真机界面验收最终确认；非 Windows 环境的 Rust 测试只证明排序过滤策略和编译合同。
