# 悬浮条密度即时生效与方案 B 左右轮廓修正规格

关联需求：REQ-20260911-013、REQ-20260911-014、REQ-20260911-015。日期：2026-09-11。状态：用户已确认方案 B“圆角 + 加强反向肩弧”。

## 问题与目标

用户在 0.8.1 现场验收中确认了三个相互关联的问题：已展开的 Compact 悬浮条在 Settings 改为 Mini 后不会立即改变尺寸；左贴边时暴露侧右上角和右下角呈尖角；贴屏侧左上角和左下角的反向肩弧太小，几乎看不出曲线变化。

本轮把设置状态、原生窗口尺寸、背景轮廓和圆环布局视为同一次外观更新。密度一经选择，当前展开的悬浮条立即按新档位重排；左右贴边共用同一条标准路径并做水平镜像，采用用户确认的方案 B 修复圆角和反向肩弧。

## 已确认的视觉基线

- Mini、Compact、Comfortable 的宽度继续为 65、78、108pt/px；圆环尺寸、间距、Logo、服务顺序、内容高度和深海背景不变。
- 方案 B 在贴屏侧把可辨认的反向肩部延展到 30pt，并以连续曲率过渡到向外展开的主体。
- 暴露侧的上角和下角增加末段缓和曲线，以竖直切线接入主体边缘，不能出现尖点、折线或突变高光。
- 上肩和下肩严格垂直镜像；左贴边和右贴边严格水平镜像。任何一侧都不维护单独的手调路径。
- 轮廓调整只作用于展开态。既有 20×96pt/px 命中窗口和 14×88pt/px 收起把手保持 0.8.1 行为。
- 不恢复底部 Settings 弧线或齿轮入口。

### 方案 B 标准路径

以右贴边 Mini 为标准坐标，宽度 `W = 65`、上肩深度 `S = 70`、展开高度为 `H`：

```text
M (65, 4)
C (63, 18) (54, 29) (37, 30)
C (18, 31) (5, 42) (1, 58)
C (0, 62) (0, 66) (0, 70)
L (0, H - 70)
C (0, H - 66) (0, H - 62) (1, H - 58)
C (5, H - 42) (18, H - 31) (37, H - 30)
C (54, H - 29) (63, H - 18) (65, H - 4)
Z
```

Compact 按 `W / 65` 缩放全部横向坐标并保持 `S = 70`；Comfortable 按 `W / 65` 缩放横向坐标，并按 `S / 70` 把肩部纵向坐标映射到 `S = 88`。下肩由上肩按展开高度计算镜像值，不重复维护数字。左贴边只对横向坐标做 `x' = W - x` 镜像。

标准路径必须满足以下几何约束：

1. 暴露侧接入竖直主体时切线为竖直方向，视觉上连续圆润。
2. 贴屏侧从端点到第一个肩部转折的纵向距离为 30pt（Comfortable 等比例映射），足以看出反向弧线。
3. 路径闭合后没有自交，背景、裁切、命中轮廓使用同一几何来源。
4. 所有密度、1–4 个服务、左右贴边时，可见圆环的完整周界都位于背景路径内。

## 密度设置即时生效

用户在 Settings 选择新密度后，当前展开悬浮条在同一次外观更新中完成以下动作：

1. 规范化并保存 Comfortable、Compact 或 Mini 偏好。
2. 取消尚未执行的展开或收起计时，保持当前悬浮条为展开态。
3. 依据新密度和当前服务数量重新计算窗口宽高、方案 B 背景路径及圆环位置。
4. 在界面线程更新原生透明窗口和内容；设置控件显示新值时，桌面悬浮条已经使用对应尺寸，不能等待自动收起或下一次悬停。
5. 保留当前物理显示器、贴边方向和垂直中心；左贴边保持窗口最小横坐标，右贴边保持窗口最大横坐标。若新尺寸超出可见区域，只执行既有的垂直夹取。
6. 更新完成后按当前自动收起偏好恢复正常计时和指针行为。

若外观更新恰好遇到窗口拖动，系统记录最后一次密度选择，并在拖动结束后的第一帧应用；仍不能借助一次收起再展开才能生效。连续快速切换只提交最后一个密度，避免旧尺寸异步回写覆盖新选择。

## 双平台数据流

### macOS

沿用 `Settings → AppModel.setStripPreferences → floatingAppearanceHandler → FloatingPanelController.applyAppearance` 链路。实现需要保证 `applyAppearance` 使用最新偏好同步重算展开尺寸，并在主线程完成窗口 frame、背景 Shape 和内容布局更新。测试必须直接观察已存在 NSPanel 的 frame 和贴边锚点，不能只验证偏好值或辅助计算函数。

### Windows

沿用 `Settings → set_strip_preferences → strip runtime/display coordinator → WebView` 链路。原生命令必须等待当前 meter 窗口按新偏好完成尺寸和位置协调，或建立等价的完成顺序后，再对前端发出设置已变化事件。异步协调中的旧请求必须带代次或被取消，避免 Compact 的迟到结果覆盖 Mini。测试同时观察 Rust 管理的原生窗口外框与 React 渲染宽度。

### 共享约束

三档尺寸、肩部参数、左右镜像和圆环包含关系属于跨平台合同。Swift Path 与 CSS/SVG clip-path 可使用各自原生表示，但必须从相同的标准坐标和缩放规则推导。背景绘制与点击裁切不得复制另一套近似轮廓。

## 实现策略比较

采用更新既有窗口的策略。它保留窗口身份、显示器、贴边位置和交互状态，通过一次明确的外观事务同时更新 frame 与内容，改动范围也与当前协调链一致。

不采用销毁并重建窗口的方案。重建容易造成闪烁、层级短暂变化、详情窗口失焦和多显示器位置丢失。

不采用等待收起或下一次悬停再读取偏好的方案。该行为正是本次已确认缺陷，且会让 Settings 显示值与桌面实际尺寸不一致。

## 失败处理

- 偏好保存成功但窗口暂时无法更新时，保留最后一次请求并在界面线程下一可用时机重试；不能显示旧偏好值，也不能用一次折叠作为恢复条件。
- 窗口不存在或被系统暂时隐藏时正常保存偏好；窗口恢复时直接以最新密度创建，不先显示旧尺寸。
- 显示器在更新期间断开时使用既有显示器回退规则，随后以新密度重新锚定，不引入新的屏幕选择策略。
- 几何参数不合法时测试和开发断言应立即失败；产品运行时回退到对应密度的最后一个有效轮廓，避免透明窗口失去可点击区域。

## 测试与验收

实现遵循测试先行，至少覆盖：

- 已展开 Compact → Mini、Mini → Comfortable 和 Comfortable → Compact 后，原生窗口宽度、背景及圆环在设置动作完成时立即变化，无需收起或再次悬停。
- 密度切换前后保持同一显示器、同一贴边方向和同一垂直中心；左右两侧的屏幕锚点误差不超过平台现有像素取整容差。
- 快速连续切换、待执行折叠计时、自动收起关闭、窗口暂时隐藏和拖动结束后，只应用最后一次密度。
- Mini、Compact、Comfortable × 1–4 个服务 × 左右贴边的背景路径严格镜像、上下肩严格镜像，圆环周界全部位于背景内。
- 方案 B 的暴露侧入口具有连续竖直切线，贴屏侧反向肩部达到规定深度；像素或路径采样能识别旧尖角与旧小弧，避免只做快照存在性检查。
- 展开态修改不改变 14pt 收起把手，不恢复底部 Settings 图标，也不改变 Provider 点击、背景拖动、右键菜单和详情行为。
- 双平台专项测试通过后再运行各自完整门禁、文档检查和独立审查。
