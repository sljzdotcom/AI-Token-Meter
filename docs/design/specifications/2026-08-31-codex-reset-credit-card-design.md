# Codex 重置券卡片视觉优化规格

日期：2026-08-31  
状态：已确认  
范围：仅优化 Codex 详情页中的重置券展示，不改变额度采集、券数据模型或兑换行为。

## 背景

当前重置券区域使用同一字号和较低对比度展示标题、数量、券类型与到期时间。信息虽然完整，但视觉层级弱，日期不易快速识别，多张券时也缺少清晰的分组结构。

## 目标

1. 一眼识别可用券数量；
2. 清楚区分每张券的类型、到期日期和剩余时间；
3. 保持与 Codex 深色详情页一致的视觉语言；
4. 支持多张券时自然向下扩展；
5. 继续保持只读，不提供领取、兑换或“立即使用”操作。

## 已选方案

采用 A「分层卡片」布局。

### 标题区

- 左侧使用重置图标与 `Reset credits` 标题；
- 右侧使用薄荷绿色胶囊显示 `N available`；
- 标题与胶囊之间保留弹性空间，使数量成为独立视觉锚点。

### 单张券卡片

- 每张券使用独立的圆角内卡片；
- 左侧为薄荷绿色重置图标容器；
- 右侧第一行显示券类型，例如 `Full usage reset`；
- 第二行突出显示完整到期日期和时间；
- 底部辅助行左侧显示 `Expiration`，右侧显示剩余天数。

### 时间状态

- 未到期：`N days remaining`；
- 当天到期：`Expires today`；
- 已过期：`Expired`；
- 没有到期信息：`Expiration unavailable`，不推测日期或剩余天数。

剩余天数按用户本地日历的自然日计算，避免用 24 小时秒数造成跨时区或夏令时偏差。

### 多张券与尺寸

- 有明确到期时间的券按到期时间从近到远排列；
- 无到期时间的券排在最后，并保持原始顺序；
- 每张券独立成卡，容器随数量向下扩展；
- Codex 详情面板允许按内容增加高度，同时受屏幕可用高度约束。

### 不完整数据

- `availableCount` 大于已返回明细数量时，在卡片列表下显示低干扰提示：`Some expiration details are unavailable`；
- 数量为零时仍显示标题区与 `0 available`，不渲染空券卡片；
- 不引入任何兑换标识、账户密钥或原始 API 响应。

## 组件边界

- `CodexResetCreditsView` 负责排序、日期状态和视觉布局；
- 纯展示辅助类型负责根据当前日期产生剩余时间文案，便于确定性测试；
- `CodexDetailView` 继续负责外层详情布局，不理解单张券内部结构；
- `CodexResetCreditsSummary` 与采集器保持不变。

## 无障碍

- 标题区读出可用数量；
- 每张券作为一个独立无障碍元素，依次读出券类型、到期日期和时间状态；
- 不仅依赖颜色区分正常、当天到期、已过期或信息缺失状态；
- 文本允许缩放，日期在空间不足时优先缩小字号而非截断关键信息。

## 测试与验收

1. 先为时间状态编写失败测试，覆盖未来日期、当天、已过期和缺失日期；
2. 测试多张券排序与无日期券置后；
3. 测试不完整明细提示条件；
4. 构建 Release App，检查单张券和多张券布局；
5. 运行完整测试，确认额度采集、缓存与其他详情页不受影响；
6. 安装并从 Codex 详情页完成真实视觉验收。

## 非目标

- 不自动使用 Codex 重置券；
- 不增加兑换按钮或确认弹窗；
- 不改变重置券获取方式；
- 不重构 Codex 官方额度或本机活动统计区域。
