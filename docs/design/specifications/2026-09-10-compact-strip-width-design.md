# Compact浮动条横向收窄设计

**需求：** `REQ-20260910-001`  
**日期：** 2026-09-10  
**发布边界：** 完成实现、测试、审查和可复核截图；不自动发布新版本。

## 目标

仅收紧Compact浮动条中圆环左右两侧的留白。48pt/px圆环、21pt/px Logo、10pt/px环间距、3.5pt/px进度线和各Provider数量对应高度全部保持不变；Comfortable、折叠把手、详情、设置与数据采集不变。

## 尺寸决定

Compact宽度由78pt/px改为70pt/px。现有48pt/px圆环在78宽度中约有15pt/px单侧空间；70宽度使其降至11pt/px，正好与macOS现有内容横向安全间距一致。该幅度能明显减少空白，同时保留大于10pt/px的背景和点击外侧空间。

Compact高度继续为1至4个Provider时的170、228、286、344pt/px。Comfortable继续为108宽及原有高度。折叠把手继续为12×96pt/px。

## 轮廓与镜像

Compact独立S形路径按原78宽基准做一次确定性的横向比例换算，得到70宽基准：

```text
M 70 12
C 64 17, 57 21, 43 22
C 19 23, 0 42, 0 70
L 0 216
C 0 244, 19 263, 43 264
C 57 265, 64 269, 70 274
Z
```

纵向坐标不变，因此上下肩部高度和反弧节奏不变。左侧贴边继续由同一轮廓水平镜像；背景继续覆盖整个单一Surface，不增加边框、阴影或拼接层。Windows可见SVG裁剪与原生窗口宽度使用同一70px合同。

## 交互与窗口

- 圆环仍位于窗口水平中心，点击区域维持48pt/px正方形。
- 非按钮背景继续作为拖动区域，圆环区域继续排除拖动。
- 密度切换、左右吸附、折叠与展开继续保留当前屏幕、边缘和归一化纵向位置。
- Windows按显示器scale factor把70 logical px换算为物理宽度，不累计缩放误差；覆盖100%、125%、150%和200%。

## 验收

- 双平台合同均报告Compact宽70、圆环48、三Provider高286，Comfortable保持108×356。
- 左右边缘镜像、1至4个Provider及展开/折叠渲染无裁切。
- 点击圆环不会触发拖动，圆环之间与肩部背景仍可拖动。
- Windows四档DPI原生窗口宽度分别为70、87或88（按平台换算）、105、140物理像素，并保持吸附。
- 输出同内容、同高度的78宽与70宽前后对比；不含真实账号或用量。

自动化覆盖尺寸、像素渲染、真实浏览器布局、原生窗口计算和不同DPI。物理Windows 11指针、多屏及系统缩放视觉仍需对应设备现场观察，不把该边界写成自动化已完成。
