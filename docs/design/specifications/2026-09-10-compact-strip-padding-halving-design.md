# Compact 圆环两侧留白减半规格

**需求：** `REQ-20260910-006`  
**基线：** v0.7.1 的 65pt/px 宽、48pt/px 圆环  
**状态：** 已选定方案，排在 `REQ-20260910-007` 后执行

## 精确尺寸

当前 Compact 宽65、圆环48，每侧留白为 `(65 - 48) / 2 = 8.5`。用户要求两侧留白各减少一半，因此新留白为4.25，逻辑总宽为 `48 + 4.25 × 2 = 56.5pt/px`。

## 方案比较与决定

1. **使用56.5逻辑宽度（采用）。** 精确满足两侧各减半；SwiftUI与CSS支持半点/亚像素，Windows原生按显示缩放换算到最近物理像素。
2. 使用57整数宽度。每侧为4.5，容易实现但不符合精确减半。
3. 保持65窗口只裁视觉背景。窗口点击、拖动和贴边占位仍然过宽，不能解决用户反馈。

## 几何与行为

- macOS `FloatingStripDensity.compact.width`、Windows原生 `logical_size`、React CSS变量和共享合同统一为56.5。
- 48圆环仍由容器居中，逻辑范围为x=4.25…52.25；纵向17内边距、10间距和1–4项高度170/228/286/344不变。
- Compact轮廓内侧边界从65移到56.5。与圆环关联的控制点随圆心左移4.25；与内侧边界关联的起点和第一控制点随边界左移8.5，保持外侧屏幕边缘x=0、肩部高度与上下反弧连续。左右侧继续镜像同一路径。
- Comfortable 108宽、折叠把手12宽、Logo尺寸、背景图、遮罩、Provider顺序及点击/拖动行为不变。
- Windows `LogicalSize<f64>::to_physical` 按缩放转换并四舍五入：1.0×约57、1.25×约71、1.5×约85、2.0×113物理像素；网页内部仍保持56.5 CSS px，圆环不裁切。

## 验收

- 双平台尺寸合同均报告56.5逻辑宽、48圆环、4.25左右留白；四种Provider数量的高度不变。
- macOS 2×渲染与Windows真实浏览器在左右边、1–4 Provider下，圆环完整、中心可点击、相邻玻璃可拖动、边角透明、主体不透明。
- Windows真实浏览器至少验证1.0×/1.25×/1.5×/2.0×换算后的物理宽度取整；实际窗口与页面布局差不超过1物理像素。
- 输出同倍率65与56.5对比图；不改变Comfortable、折叠把手和纵向尺寸。
