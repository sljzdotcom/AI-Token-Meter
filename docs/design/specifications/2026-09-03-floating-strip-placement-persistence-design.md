# 浮动条位置稳定持久化设计

**需求：** `REQ-20260903-009`

**日期：** 2026-09-03  
**状态：** 已确认（用户选择方案 A，并补充多显示器与单显示器切换规则）

## 问题与证据

macOS 当前已经在 `UserDefaults` 保存侧边偏好、最后解析侧边、归一化垂直位置和显示器编号。用户现场配置仍明确记录 `automatic + left + 约 48% + screen 3`，说明拖动保存本身有效。

失效发生在恢复链路：当前实现把 `NSScreenNumber` 当成持久显示器身份。该编号可能在重启、休眠唤醒、显示器重新连接或显示拓扑变化后改变。找不到已保存编号时，普通重排路径会选择主屏幕的右侧中点，并把这个临时回退持久化为 `automatic + right + 50%`。因此一次短暂的屏幕枚举缺失就能永久覆盖用户的左侧位置。面板当前所在屏幕又参与无保存标识时的选择，可能进一步令浮动条从主屏漂移到副屏。

Windows 已在 `%APPDATA%\AI Token Meter\settings.json` 保存 `edge`、`meterVerticalPerMille` 和 `meterMonitorId`；其显示器缺失回退目前不会写回配置，但需要用合同测试锁定与 macOS 相同的行为语义。

## 目标

- 持久保存用户最后明确选择的物理显示器、Left/Right 侧边和相对垂直位置。
- 重启、休眠唤醒、活动 Space、分辨率或显示器参数变化不得擅自改变这些值。
- 多显示器状态下，只要目标显示器仍存在，浮动条不得因主屏变化、面板当前屏幕或枚举顺序而跳到另一块屏幕。
- 多屏变单屏且目标显示器不可用时，浮动条临时显示在当前主屏幕，并沿用已保存的侧边和相对高度。
- 临时回退不得覆盖原目标；目标显示器重新出现后自动恢复到它。
- 用户在回退状态下主动拖动或通过 Settings/辅助功能改变位置时，才把当前屏幕作为新的明确目标保存。
- 兼容升级前保存的数字显示器编号，不要求用户重新设置。

## 方案比较

### A. 稳定显示器身份 + 无损临时回退（采用）

macOS 使用 Core Graphics 提供的显示器 UUID 作为持久身份，同时保留一次性旧数字编号匹配迁移。屏幕缺失时只计算现场回退位置，不写入偏好。显示器参数和 Space 通知都只重新解析已保存目标。

优点：同时解决重启回右侧、主副屏漂移和临时断屏覆盖；现有位置自动迁移；不新增用户维护成本。代价是需要新增纯身份/解析策略和迁移测试。

### B. 只禁止写回右侧默认值

保留 `NSScreenNumber`，屏幕缺失时沿用左侧和高度。能缓解最明显的回右侧问题，但重启后仍不能可靠识别原物理显示器，多屏漂移仍可能发生，因此不采用。

### C. 增加可手工编辑的位置配置文件

公开显示器 ID、侧边和坐标给用户修改。它会暴露平台内部标识，容易因错误值损坏布局，并且不能修复运行中错误覆盖，因此不采用。

## 配置与身份模型

macOS 继续使用系统管理的 `~/Library/Preferences/com.millerpan.AIMeter.plist`，不引入第二份配置源。现有侧边和垂直位置键保持兼容；显示器字段升级为带类型的稳定 UUID。运行时显示器身份同时提供：

- `stableIdentifier`：由当前 Core Graphics display ID 解析出的显示器 UUID；
- `legacyIdentifier`：升级前使用的 `NSScreenNumber` 字符串，只用于迁移匹配；
- `isMain`：本次屏幕拓扑中的当前主屏标志。

如果旧数字标识仍匹配当前屏幕，应用只把显示器标识迁移为稳定 UUID，侧边、垂直位置和 Automatic/Left/Right 偏好保持不变。若旧标识无法匹配且当前只有一块屏幕，可安全绑定该主屏并迁移；多屏下无法确定旧目标时先在主屏无损回退，直到用户主动摆放。

Windows 继续使用现有 JSON 配置和原子写入机制。此次至少锁定目标屏优先、主屏回退不写回、用户拖动才更新目标的对等合同；不会增加另一份位置配置。

## 解析与写入规则

每次启动、显示器参数变化、活动 Space 切换或显隐浮动条时，按以下顺序解析：

1. 已保存稳定 UUID 存在于当前屏幕集合：选择该屏幕，沿用保存的侧边和高度。
2. 已保存旧数字编号能匹配：选择对应屏幕，迁移为其稳定 UUID，其他位置字段不变。
3. 保存目标不可用：选择 `NSScreen.main`；主屏暂不可用时才选择屏幕集合第一项。沿用已保存侧边和高度，不写入任何位置字段。
4. 没有历史目标：首次运行使用当前主屏、默认右侧和中点；第一次用户移动后保存稳定身份。

允许写入位置的入口只有：

- 指针拖动结束；
- Settings 切换明确侧边；
- 键盘或 VoiceOver 位置操作；
- 无损的旧标识到稳定 UUID 数据迁移。

启动、`show()`、普通重新定位、活动 Space 和 `didChangeScreenParameters` 通知不得把现场回退写回配置。

## 多显示器状态转换

| 场景 | 结果 | 是否改配置 |
| --- | --- | --- |
| 目标主屏与副屏都在线 | 固定在保存的目标屏、侧边和高度 | 否 |
| 当前主屏角色切换，但目标屏仍在线 | 仍留在原物理目标屏 | 否 |
| 目标屏断开，只剩一块屏幕 | 回到当前主屏相同侧边和相对高度 | 否 |
| 目标屏断开，仍有多块其他屏幕 | 只回到当前主屏，不选择任意副屏 | 否 |
| 原目标屏重新接入 | 自动回到原目标屏 | 否 |
| 回退期间用户主动拖动 | 吸附并保存用户此次选中的屏幕、侧边和高度 | 是 |

## 错误处理

- 无法取得显示器 UUID 时，本次运行仍可使用带命名空间的旧编号作为临时身份，但不得因此恢复右侧默认值。
- 屏幕集合短暂为空时保持现有面板位置，不清空配置；下一次系统通知再解析。
- 损坏或未知侧边继续采用现有安全默认值；合法的已保存左/右侧不得因显示器错误而被重置。
- 位置迁移写入失败不阻断显示，后续启动可再次迁移。

## 测试与验收

- 失败先行单元测试复现：保存 Left 后目标屏暂不可用，普通重排不得返回右侧中点或请求持久化恢复。
- 身份测试覆盖稳定 UUID、旧数字编号匹配、单屏旧配置迁移和 UUID 不可用回退。
- 多屏策略测试覆盖目标屏优先、主屏角色变化不漂移、断屏只回主屏、重连恢复和回退不写回。
- AppModel/存储测试覆盖迁移只改显示器身份，不改侧边、高度和偏好。
- Windows 合同测试确认已有 JSON 位置字段完整保存，目标缺失选择主屏但不改配置。
- 完整 macOS Swift 测试、Windows Rust/前端测试、文档与公开安全门禁通过。
- 有条件时在真实双屏环境验收：主屏/副屏分别摆放、重启、休眠唤醒、拔插和单屏回退。没有第二块屏幕时如实保留真机补验项，不以单元测试冒充物理拔插证据。

## 非目标

- 不提供手工编辑显示器 ID 的高级界面。
- 不同步不同 Mac 或不同 Windows 电脑之间的位置。
- 不改变浮动条轮廓、背景、Logo、详情布局、窗口层级或自动隐藏。
- 不把临时回退理解为用户永久更换目标屏幕。
