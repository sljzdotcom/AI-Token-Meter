# 悬浮条自动隐藏展开终态统一规格

关联需求：REQ-20260912-001。日期：2026-09-12。状态：用户现场对照已确认问题。

## 问题

v0.8.2 中，关闭自动隐藏时，Comfortable、Compact、Mini 的展开悬浮条四周均为圆润的方案 B 轮廓。开启自动隐藏后，从收起把手悬停展开的同一悬浮条却会显示尖锐边缘。用户还观察到从 Settings 选择 Mini 时，当前展开内容有时没有可见变化，只有经历一次自动隐藏和重新悬停后才显示 Mini。

现有 macOS 路径在常驻展开或设置变更时直接提交最终窗口 frame；自动隐藏展开时则通过 `NSWindow` frame 动画从 20×96pt 收起窗口拉伸到密度对应尺寸，并在固定 180ms 后显示内容。窗口动画过程会把透明内容层和 Shape 一起缩放，动画结束点没有再次用最终 frame 重新布局和绘制，因而终态可能保留过渡帧的拉伸/裁切结果。此前设置回归只检查未显示 NSPanel 的外框宽度，没有覆盖可见窗口、自动隐藏展开和最终像素轮廓。

Windows 也有收起与展开两条原生窗口尺寸路径，需保留跨平台相同行为合同并验证最终窗口尺寸、前端密度和轮廓一致。

## 目标行为

- 自动隐藏关闭、设置变更强制展开、自动隐藏悬停展开，最终都调用同一个“提交展开终态”操作。
- 展开终态先使用当前最新密度和可见服务数量计算窗口尺寸，再更新窗口位置、内容布局和方案 B Shape；不能从收起窗口的中间缩放结果充当最终绘制。
- 保留内容淡入淡出的时间感，但窗口本身不得从收起尺寸拉伸；展开时先无动画提交精确终态，再显示内容。
- 动画进行中若密度再次改变，旧任务必须取消；最终提交只读取并应用最后一次偏好。
- Settings 选择 Mini 时，正在显示的窗口立即落到 65pt/px 宽度及对应圆润路径，不依赖自动收起、悬停或重新创建窗口。
- Comfortable、Compact、Mini 的最终轮廓继续使用已发布的方案 B 标准几何、上下垂直镜像和左右水平镜像。先修复状态路径，不另行手调三套形状。
- 收起把手保持 20×96pt/px 命中窗口与 14×88pt/px 可见轮廓。

## 实现决定

macOS 让常驻展开、设置变更和自动隐藏展开都经过现有的精确 frame 布置入口，移除对异形透明窗口本身的 frame 拉伸动画。展开时立即按最新密度提交窗口尺寸和内容布局，保留180ms内容淡入；淡入前再次读取最新偏好并提交精确终态。收起时保留140ms内容淡出，再直接提交20×96pt窗口。取消或被新外观更新取代的任务不能回写旧状态。

Windows 保持现有原生协调回执顺序，并增加从折叠态展开到三种密度的合同测试，确认原生尺寸和 React/SVG 轮廓使用同一份最新设置。如果复现证明 Windows 也会保留过渡窗口形状，则在原生恢复完成后增加同等终态提交；若专项证据表明当前路径已正确，则不做无依据改动。

## 验收

- 可见 macOS NSPanel 分别以三种密度执行常驻展开与“收起→展开”，等待动效完成后 frame、内容 bounds 和像素 alpha 轮廓一致。
- Compact→Mini、Comfortable→Mini 在设置调用返回后立即为 65pt，并在下一次布局周期内呈现 Mini 的完整圆润轮廓。
- 动画期间切换密度时，最终只出现最后选择的密度。
- 三密度、1–4 个服务、左右贴边的上下肩镜像、外侧圆角和圆环完整包含回归继续通过。
- Windows 前端、原生窗口尺寸、自动隐藏状态机与真实 Chromium 密度门禁通过。
