# 多显示器展示与自由拖动规格

需求：REQ-20260907-001。用户已批准推荐方案并授权按推荐直接实施。

## 行为

- Settings → Appearance 提供 Primary display、Selected display、All displays；新安装默认 Primary，旧配置有目标则迁移为 Selected，保留边缘和高度。
- 指定屏幕列表用系统名称及主屏/内置标记区分，保留离线目标说明；Move to primary display 可立即找回浮动条。
- 单屏模式拖动时允许横向和纵向移动；以指针所在完整屏幕选目标，松手后按 Left/Right 或最近边缘吸附，转为 Selected 并保存目标。固定边缘不能阻止跨屏拖动。
- All displays 每个在线非镜像屏各有一个浮动条；每屏独立边缘/高度，共享字体、密度、Provider 顺序。每个实例拖动留在所属屏，不制造重复实例。
- Screen edge 为共享约束：Left/Right 强制所有展示使用该侧，Automatic 恢复各屏记住的边缘；固定侧只限制松手位置，不限制单屏模式跨屏拖动。
- 上述 Automatic/固定侧约束适用于已有此选项的 macOS；Windows 延续原来的 Left/Right 摆放选择，拖动按最近边缘吸附，不额外增加 Automatic。两平台一致的是选屏、位置保存、断屏回退与详情所有权。
- 目标离线时主动改边或无障碍移动属于新的用户摆放操作，会将临时借用的当前屏设为指定目标；原离线屏的位置记录仍保留。
- 正常 Primary 模式下改边/无障碍移动仍保持 Primary，只有拖动明确选择屏幕时转为 Selected。
- 用稳定屏幕身份保存位置。目标离线时临时回系统主屏且保留原目标及记录；重连恢复。无屏时不写默认值；拓扑变化取消当前拖动再重排。
- macOS 系统主屏使用实时 NSScreen.screens 首项，不使用焦点屏 NSScreen.main；此条取代旧位置规格中的 main 假设。
- 拖动期间不接受刷新/外观/折叠导致的自动定位，结束后立即恢复；负坐标、上下错位屏、不同尺寸均可处理。

## 所有权

新增窗口协调层管理实例与拓扑；采集、CLI、缓存、账户和通知始终共用一个 AppModel/运行时。任何时刻只显示一个详情；点击另一屏先关闭旧详情并释放其内容，再呈现新详情，DeepSeek WebView 不能有两个宿主。删除实例必须释放事件监控、计时器和窗口。

## 持久化与兼容

在原有偏好旁新增版本化显示模式和每屏位置表；旧数据仅迁移一次。自动回退不写位置，只有用户拖动、改边或主动选屏才更新。Windows 遵守相同模式语义，使用现有稳定设备 ID 与拓扑监控，不依赖数组下标。

旧数字编号仅在实际匹配时迁移，不再因“只剩一屏”推测为同一显示器；不匹配时保留旧目标并临时回主屏。

## 验收

自动化覆盖旧配置迁移、主屏非焦点屏、选屏与所有屏解析、断开/重连不覆盖、独立位置、固定边缘跨屏拖动、详情唯一所有权及释放。运行完整 Swift、Windows Rust/前端与文档门禁。真实双屏、睡眠/唤醒、DPI 和镜像切换另记现场证据，不以单屏测试代替。
