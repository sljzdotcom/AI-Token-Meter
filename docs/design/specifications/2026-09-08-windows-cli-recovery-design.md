# Windows 已登录 CLI 发现与额度恢复

日期：2026-09-08。关联：REQ-20260908-001。按用户持续授权采用推荐方案，无额外视觉选择。

## 证据与范围

用户确认 Codex 0.153.4 的 npm 包装器在用户 npm 目录，Node 在独立的 Program Files 目录。现有受限进程环境仅把实际启动程序所在目录放入 PATH，因此 cmd 包装器无法通过 PATH 找到 Node。账户发现保留 Missing/Unavailable 区分，额度发现却将所有失败折叠为未安装。Claude 账户已连接，额度采集仍在用户主目录运行，可能遇到独立的工作区确认；尚不能证明远端每次失败都由此造成。

只修复 Windows；不改 macOS、登录凭据、安装路径、配色、字体和更新通道。不重装 CLI，不自动登录，不自动信任目录，不记录用户账号、令牌或实际主目录。

## 选择与行为

1. 对标准官方 Codex npm 安装结构，定位包的真实 JS 入口及独立 Node，通过结构化参数直接执行。验证包身份/入口，不解析任意 shell 文本为命令，不扩大为继承整个终端环境。保留原生 exe、显式配置和 WSL 优先规则。
2. 账户、登录和额度使用一致的有界发现策略。确实缺失才显示未安装；已找到但不能执行显示暂不可用；取消保持取消。错误不能触发重装建议或抹掉已登录身份。
3. Claude 原生额度采集使用应用专用空工作区。Settings 的 Claude 服务提供“初始化额度读取”，用户点击后打开官方 CLI，工作目录与采集一致，由用户自己确认。不发送信任回答；不读写 CLI 信任配置。WSL 使用发行版内专用目录，不能误用 Windows 用户目录。
4. 初始化启动不代表完成。显示完成后检查状态/刷新提示；显式检查状态清除旧认证/设置等可恢复阻塞并重新采集额度，但不将账户连接当作额度成功。服务端限流等待必须保留，不能通过手动检查绕过；自动 focus/轮询检查不触发额度重试。

## 验收与安全

- 分离 npm/Node 目录、路径含空格、缺少 Node、非官方包装器、原生 exe、显式路径、WSL 均有回归覆盖。
- Windows 原生进程测试在受限环境下真正执行 npm 入口，不仅模拟健康检查返回 true。
- 发现错误分类、取消、超时和已有登录信息不被覆盖；有界输出和子进程清理保留。
- Claude 收集与初始化工作区一致；用户主目录不是默认受信任区；按钮中英文、忙碌状态、错误反馈及刷新流程可测试。
- 本机自动化、原生 Windows CI、用户 Windows 真机验收分别记录，不互相冒充。
