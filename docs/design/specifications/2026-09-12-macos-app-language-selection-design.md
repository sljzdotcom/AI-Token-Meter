# macOS 三语言即时切换规格

关联需求：REQ-20260912-002。日期：2026-09-12。状态：推荐方案已获用户原则确认，等待书面规格审阅。

## 目标

macOS版Settings → Appearance在Display分组首项增加Language选择器，固定提供`English`、`简体中文`、`繁體中文`。新安装、旧版本升级和无法识别的存储值都使用English，不跟随系统语言自动改变。用户选择后无需重启，当前打开及随后创建的应用窗口立即使用所选语言。

语言范围覆盖AI Token Meter拥有的macOS界面：Settings五个页签、菜单栏面板、浮动条与Provider详情、应用内更新状态、操作结果与错误提示、右键菜单、系统通知以及辅助功能名称和值。日期、时间和数字的可见格式跟随所选语言。

以下内容保持原文：`AI Token Meter`、`Claude Code`、`OpenAI Codex`、`DeepSeek`、`Google Antigravity`及其他产品/命令名；官方CLI、Terminal、Sparkle或系统提供的界面；DeepSeek官网等第三方网页；服务端或CLI返回的原始诊断。不能为翻译而改写协议值、持久化标识、采集解析或业务判断。

REQ-20260912-003的Services产品Logo是后续独立事项，不混入本规格的实现和验收。

## 方案比较与选择

选择应用内显式语言状态：把语言作为`AppModel`的可观察偏好，在所有SwiftUI根视图注入对应`Locale`，动态文本通过同一翻译入口按显式语言解析。这能满足固定默认英文、即时切换、所有独立悬浮窗口一致和可测试持久化。

未选择修改进程级`AppleLanguages`后重启。该方案接近传统Bundle本地化，但无法即时更新，且会修改应用外部偏好。也未选择只翻译Settings；那会使设置、详情、菜单和提示混用语言，违背用户以语言选择控制应用界面的预期。

## 偏好模型

新增macOS专用`AppLanguage`值类型，存储值固定为`en`、`zh-Hans`、`zh-Hant`，显示名固定为各语言自称：`English`、`简体中文`、`繁體中文`。它提供用于显示格式的Locale标识，但存储值不依赖`Locale.current`。

新增单一职责的偏好存储，使用现有`UserDefaults`依赖注入方式。缺失、空值、历史未知值和未来无法识别值统一回退`.english`并在内存中规范化；不修改Windows的`locale`字段或共享跨平台设置合同。`AppModel.setAppLanguage`在值实际变化时保存并发布观察更新，同值写入不重复触发副作用。

## 本地化资源与运行时

应用target在现有Resources下增加English、简体中文和繁体中文资源。English是完整的源语言清单，另外两份资源必须拥有相同键集合；测试拒绝缺键、重复键和空翻译。翻译键使用稳定语义，不把整段带变量的最终字符串当业务状态保存。

SwiftUI的静态标题、标签和按钮从资源中解析，并由根视图注入的显式Locale重绘。`AIMeterApp`中的MenuBarExtra与Settings是两个根视图；`FloatingPanelController`另外创建浮动条和详情`NSHostingView`，三处都必须读取同一个可观察语言值，确保切换后已有窗口和后来重建的详情一致。

AppKit菜单、系统通知、动态错误、带Provider名/百分比/日期的句子和辅助功能字符串不能依赖进程级Bundle语言。它们使用显式语言的本地化接口，并以命名参数插入动态值。瞬时设置消息保存语义状态和参数，显示时再翻译，避免切换语言后旧消息继续停留在上一语言。

日期和数字格式显式使用所选Locale。持久化JSON、命令行输入输出、解析用`en_US_POSIX`格式及更新签名内容不受界面语言影响。

## Appearance交互

Language Picker位于Display font之前。标签随当前语言翻译，三个选项始终显示自己的名称，避免用户切到不熟悉的语言后无法找到返回选项。选择立即保存并更新当前Settings、菜单栏面板和所有浮动窗口；不弹重启提示。

Appearance现有Display font、Restore Default Font和字体安装说明继续位于Language下方。设置窗口尺寸、五页签顺序、系统字体隔离和键盘操作保持。

## 翻译口径

简体中文使用中国大陆常见产品界面用语；繁体中文使用自然繁体表达，不做逐字简繁转换。固定示例：

| English | 简体中文 | 繁體中文 |
| --- | --- | --- |
| Appearance | 外观 | 外觀 |
| Floating Strip | 悬浮条 | 懸浮條 |
| Monitoring | 监测 | 監測 |
| Services | 服务 | 服務 |
| About | 关于 | 關於 |
| Language | 语言 | 語言 |

技术名词如API Key、CLI、Token可保留通行英文，并在中文句子中保持一致。中文标点、空格和变量顺序由各自翻译定义；不能把英文语序通过字符串拼接强加给中文。

## 测试与验收

- 偏好测试先证明当前实现缺少语言模型：无值、`en`、`zh-Hans`、`zh-Hant`和未知值分别得到预期结果，切换后重建`AppModel`仍保持选择。
- 资源完整性测试读取三份语言资源，验证键集合相同、值非空，并检查固定品牌名没有被翻译。
- Appearance结构测试验证Language位于Display font之前，三个选项顺序固定且使用自称。
- 视图与动态文案测试在三种显式Locale下核对五个页签、主要设置分组、菜单栏操作、四个Provider详情状态、错误/恢复信息、通知和辅助功能字符串。
- 即时切换测试在同一`AppModel`及已存在的浮动窗口上选择语言，确认文本观察更新，不依赖窗口关闭、应用重启或系统语言。
- 日期和数字测试使用固定时间和值，证明界面格式随语言变化，同时现有采集解析与持久化序列化结果不变。
- 完整Swift测试、可见窗口/渲染专项、Release App资源打包、文档检查和公开安全检查通过。Windows源码、前端测试和原生构建保持原结果；若共享合同未改，不为macOS专用功能制造Windows产品变化。

## 完成边界

本需求完成条件是三语言资源、偏好持久化、即时更新、动态文本和主要界面覆盖均有自动化证据，并通过独立审查与本地主分支整合。物理显示器与系统通知的最终视觉可以保留现场验收，但不得用它代替资源、持久化和视图回归。

当前用户没有授权远程推送、版本号变更、标签、GitHub Release或更新源修改；这些动作不属于本规格。
