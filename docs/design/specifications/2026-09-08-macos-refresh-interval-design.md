# macOS 可编辑用量刷新间隔

关联需求：REQ-20260908-010。日期：2026-09-08。需求提交 `be758f1`，在独立分支由 `99e0dd8` 安全引入，保留 REQ-009 交付成果。

## 诊断证据与决定

`MonitoringSettingsView` 渲染 `LabeledContent("Refresh interval", value: "5 minutes")`，是不可编辑静态文本。`AppModel.start()` 循环直接 `Task.sleep(for: .seconds(300))`，没有刷新间隔偏好键、setter 或可变调度。当前指南也写 macOS 固定五分钟。该问题指向用量刷新间隔，不是软件版本更新检查。

推荐补齐原生编辑→保存→计时→重启恢复链路，沿用项目 Windows 的合法范围 30 至 86400 整数秒，默认 300 秒。macOS 使用系统字体的原生数字文本输入，显示 seconds 单位、允许范围及默认五分钟提示；用 Apply 或回车明确提交。输入非法/空白/小数/超范围时提示并保留已保存值。采用明确提交避免每个按键都改变倒计时；不增加新的产品配置面板。

## 调度语义

启动保持原有一次身份检查及自动用量刷新。有效保存立即更新显示和 UserDefaults；若正在等待旧周期，取消旧等待并按新间隔重新计时，不额外刷新、不重复身份检查、不取消登录任务。正在进行的采集不被改间隔取消、不产生并发采集；完成后使用新间隔。重复保存相同值不扰动调度。停止应用模型后不再触发定时刷新；迟到的旧等待不能引发重复请求。

周期刷新仍传 `manual: false` 进入既有 RefreshCoordinator；不清除或绕过 Retry-After、认证/网络退避，不改手动刷新、软件版本更新、Windows、Widget 更新策略。缺少或损坏存储回退默认值，不覆盖其他偏好。以可控时钟/等待边界验证调度，不把真实账号或真实分钟等待用于自动测试。

## 验收

1. 真实原生控件可编辑，Apply/回车提交的值与模型和偏好一致；重建模型/界面后保留。
2. 30/300/86400 等合法值可用，非法内容和越界不会破坏旧值；字体、焦点、标签可访问。
3. 旧等待被新值替代，下一次刷新遵循新值；修改时正在采集不重复、不被中断；停止/连续修改无迟到刷新。
4. 默认仍五分钟；既有刷新退避测试及相关 AppModel 测试通过。
5. 提供红绿复现、原生 UI/调度回归、完整 Swift 测试、Release 构建、文档检查和独立审查。若无法在用户真实应用现场验收，要清楚区分原生测试宿主与用户安装包。
