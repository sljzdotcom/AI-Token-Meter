# 浮岛轮廓、拖动与设置入口回归修复设计

## 背景

贴边视觉版本完成安装后，真实界面暴露出四项回归：浮岛上下连接段显示为方形、顶部出现不符合预期的短横、用户无法可靠拖动浮岛，以及菜单栏面板中的设置按钮不能打开设置窗口。本规格只修复这四项，不改变额度数据、详情页内容或服务采集逻辑。

## 已确认结果

- 左右贴边时都使用此前批准的反向半圆连续轮廓；
- 浮岛是一整块玻璃材质，不显示独立端帽、框线或接缝；
- 移除顶部可见短横；
- 三个服务 Logo 继续只负责打开详情；其余可见玻璃背景均可开始拖动；
- Automatic 模式允许跨边拖动，Left 和 Right 模式只改变垂直位置；
- 菜单栏齿轮必须可靠打开并置前设置窗口。

## 根因

### 轮廓偏差

当前 `FloatingStripShape` 使用通用肩部、内缩和圆角参数重新近似轮廓，没有忠实实现已批准原型的 SVG 路径。路径在贴边侧保留了明显直线矩形段，因此真实桌面上呈现为上下方块，而不是反向半圆内收。

### 横线与拖动

顶部短横是唯一的拖动手柄。它的可点击范围约为 `50 × 18` 点，既成为不必要的视觉元素，也要求用户精确命中很小的区域。布局和位置计算已有自动化覆盖，问题发生在输入入口而不是吸附算法。

### 设置窗口

菜单栏面板当前直接使用 `SettingsLink`。应用同时使用 `LSUIElement` 和窗口式 `MenuBarExtra`；在当前运行环境中，系统链接关闭弹出面板后没有可靠激活并置前设置场景。设置场景本身仍然存在。

## 设计

### 反向半圆连续路径

`FloatingStripShape` 以 `108 × 356` 的批准原型为基准，用归一化坐标表达同一条连续路径：

- 贴边侧从窗口顶部沿屏幕边缘贯穿到底部，保证零间距；
- 顶部从屏幕边缘向桌面内部平滑内收，经过短颈后连接中央圆角主体；
- 底部使用垂直镜像的同类曲线；
- 左侧使用水平镜像，不维护第二套几何；
- 不增加 `stroke`、独立 Shape 或叠加端帽。

测试除验证完整窗口边界外，还要检查顶部、短颈、主体和底部的代表性点是否处于预期的内外区域，防止只凭 `boundingRect` 通过而再次退化成方形。

### 背景拖动

可拖动命中区域由单独的纯值命中模型定义。三个 60 点服务按钮区域被排除，剩余浮岛形状内部均属于拖动背景。SwiftUI 视图把拖动手势绑定到背景表面，而不是绑在短横上。

拖动仍然复用 `FloatingPanelController` 的现有回调和 `FloatingStripLayout`：

- 开始和变化阶段实时移动；
- Automatic 根据指针落点选择最近侧边；
- 固定 Left/Right 忽略水平位移；
- 松手保存显示器、侧边和归一化垂直位置。

服务按钮保持较高命中优先级，普通点击不会触发拖动；从玻璃空白处开始的拖动不会打开详情。背景拖动区域提供 `openHand`/`closedHand` 光标反馈，并继续暴露现有键盘与 VoiceOver 移动动作。

### 设置入口

`MenuBarPanel` 从环境读取 macOS 官方 `OpenSettingsAction`，把齿轮改为普通 `Button`。点击时按以下顺序执行：

1. 激活 AI Meter，使 `LSUIElement` 应用可以把窗口置前；
2. 调用 `openSettings()` 打开或置前已声明的 `Settings` 场景。

设置动作包装为小型可注入命令，以便测试点击顺序而不依赖真实系统窗口。若设置窗口已经存在，同一动作只将其置前，不创建重复业务状态。

## 错误处理与边界

- 没有可用屏幕时沿用现有无操作回退；
- 拖动过程中切换侧边偏好时，以最新偏好完成吸附；
- 点击透明窗口区域不能启动拖动，只有 Shape 内实际玻璃区域参与命中；
- 设置动作不改变应用的 `LSUIElement` 属性，也不在 Dock 中常驻图标；
- 不引入私有选择器或旧版 `showPreferencesWindow:` 回退。

## 测试策略

采用红—绿测试驱动循环：

1. 轮廓测试先证明当前方形肩部不满足批准路径的代表性命中断言；
2. 拖动命中测试先证明当前只有手柄、背景没有可用拖动区域；
3. 设置动作测试先证明当前链接没有显式的“激活后打开设置”顺序；
4. 最小实现后运行相关测试，再运行完整 `scripts/test.sh`；
5. Release 构建、`codesign --verify --deep --strict`、产物哈希和安装包哈希必须通过；
6. 实机分别验收左右反向半圆、空白背景拖动、Logo 点击和菜单设置窗口。

## 验收标准

- 截图中的上下方块消失，轮廓与批准原型的反向半圆一致；
- Claude 上方不再显示短横；
- 用户可从 Logo 之外的玻璃区域拖动，Logo 点击仍正常；
- 左右镜像、Automatic/Left/Right 和垂直位置记忆保持正确；
- 菜单栏齿轮每次都能打开或置前设置窗口；
- 无新的透明边缘、按钮误触、详情展开或可访问性回归；
- 完整测试、正式构建、签名和真实安装验收均通过。
