# AI Meter 用量准确性修复设计

## 目标

修复 Claude 与 Codex 的已知额度误判，并保证悬浮圆环、中央数字和详情窗口使用一致、可解释的数据语义。

## 已确认问题

1. Claude `/usage` 中的“weekly limits promo +50%”被通用百分比解析器当成周额度已使用 50%。
2. Codex 顶层 `rateLimits` 返回通用周额度已使用 5%，但采集器因其没有 secondary 窗口而用 `codex_bengalfox`（Spark 专用额度）整体替换，最终错误显示 0%。
3. 圆环把 0% 或无百分比强制提升到 4% 弧长，因此零用量也看起来像发生了消耗。
4. 展示模型的圆环取主、次额度最大值，中央数字只取主额度；当两个窗口不同，二者会表达不同指标。

## 方案 A（已批准）

### Claude 解析

- 只把具备用量语义的百分比行转换为指标。
- 英文用量行必须包含 `used`、`remaining` 或 `left`，中文用量行必须包含 `已用`、`使用`、`剩余` 或 `可用`；现有带进度条的测试格式继续支持。
- 促销、说明、日期和链接中的百分比不产生指标，也不能覆盖此前已解析的同名额度。
- 使用包含真实 Claude 2.1.251 页面结构和 `+50% weekly limits promo` 的 fixture 建立回归测试。

### Codex 额度选择

- 顶层 `result.rateLimits` 是通用额度的权威来源，始终保留，不因缺少 secondary 而被模型专用额度整体替换。
- 当前顶层通用窗口为 10080 分钟时，将其标记为 `Weekly limit` 并显示官方 `usedPercent`。
- `rateLimitsByLimitId` 仅用于补充与顶层不同、且能明确识别的时间窗口；不得用 Spark、reserve 或其他模型专用额度覆盖通用额度。
- 本次最小实现不把模型专用额度混入通用圆环；详情只显示已确认的通用窗口。

### 展示一致性

- 对有界百分比指标，选择主、次窗口中 `usedFraction` 最大的指标作为摘要指标。
- 圆环弧长和中央百分比都来自同一个摘要指标；详情仍逐项展示各窗口和重置时间。
- 0% 时不绘制前景弧；无百分比的余额型指标也不伪造进度弧，只保留背景轨道和余额文字。
- 菜单栏最高风险语义继续基于有效的最高已用比例，不改变阈值规则。

## 数据流

1. Claude 文本或 Codex 结构化响应进入各自采集器。
2. 采集器只生成经过业务语义验证的 `UsageMetric`。
3. `ProviderPresentation` 选择摘要指标，同时生成一致的 `fraction` 与 `valueText`。
4. `UsageRing` 只在摘要比例大于 0 时绘制前景弧。
5. 详情卡继续读取快照中的各个真实指标，不使用装饰性数值。

## 测试与验收

- Claude fixture：当前会话 0%、周额度 0%、促销提高 50%；断言两个指标均为 0%，不存在 50% 指标。
- Codex fixture：顶层通用周额度 5%，Spark 专用额度 0%/0%；断言摘要和主指标均为 5%，不选择 Spark。
- 展示模型：主额度 0%、次额度 10%；断言圆环比例和中央文字都为 10%。
- 圆环绘制逻辑提取为可测试的纯值：0 和 nil 返回不绘制，正数按 0...1 截断。
- 运行解析器、采集器、展示模型专项测试，随后运行全部测试、真实 CLI 冒烟测试、release 构建、签名验证和安装后界面验收。

## 安全与范围

- 不读取或记录 Claude/Codex 登录令牌、账号信息或完整原始响应。
- 不改变登录、Keychain、刷新周期、通知阈值和 DeepSeek 请求逻辑。
- 不增加双层圆环、模型切换器或新的设置项。
