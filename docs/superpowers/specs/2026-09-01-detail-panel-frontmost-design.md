# AI Token Meter 详情窗口置前设计规格

**日期：** 2026-09-01  
**状态：** 已实施并验收
**范围：** 浮动条 Provider 点击后出现的详情窗口  
**需求：** `REQ-20260901-005`

## 1. 问题与根因

浮动条和详情窗口目前都通过 `FloatingPanelPresentationPolicy.apply(to:)` 使用同一个桌面窗口层级。这个层级高于桌面图标、低于普通应用窗口，适合只在桌面显示的浮动条，却不适合用户点击后需要立即阅读或交互的详情窗口。

`orderFrontRegardless()` 只能让窗口在自身层级中置前，不能跨越更高的普通窗口层级，因此桌面已有应用窗口时，详情窗口会留在这些窗口下方。

## 2. 目标

1. 用户点击 Claude、Codex 或 DeepSeek 图标后，详情窗口位于所有普通应用窗口上方。
2. 浮动条继续保持桌面层级，不在全屏应用上方显示。
3. 详情窗口只在显示期间置前，关闭后从窗口栈移除，不形成永久置顶窗口。
4. Claude、Codex 的只读详情不强制抢走键盘焦点；DeepSeek 的交互详情继续获得键盘输入能力。
5. 点击空白区域、自动隐藏、切换 Space 和关闭浮动条的既有行为保持不变。

## 3. 方案

为 `FloatingPanelPresentationPolicy` 增加明确的窗口角色：

- `strip`：继续使用“桌面图标层级 + 1”；
- `detail`：使用 `NSWindow.Level.floating`，高于普通应用窗口、低于系统模态及屏幕保护层级。

两个角色共享现有 `collectionBehavior`，继续加入普通 Spaces、忽略窗口循环且不加入全屏 Space。`FloatingPanelController` 创建窗口时传入角色，不在每次点击时重复修改层级。

详情显示方式保持 Provider 差异：

- Claude、Codex：`orderFrontRegardless()`，窗口置前但不激活应用、不抢键盘焦点；
- DeepSeek：先激活应用，再 `makeKeyAndOrderFront()`，以便 WebView 输入。

## 4. 非目标

- 不把浮动条本身提升到普通窗口上方。
- 不使用 `.screenSaver`、系统模态或其他会覆盖系统界面的极高层级。
- 不改变详情页尺寸、位置、字体、配色、自动隐藏时长或点击空白关闭逻辑。
- 不让详情页跨越到当前全屏应用的 Space。

## 5. 测试与验收

自动化测试必须证明：

1. `strip` 仍高于桌面图标且低于普通窗口；
2. `detail` 等于标准 `.floating` 层级且高于 `.normal`；
3. 两种角色继续使用相同的普通 Space 行为；
4. 应用策略后两个面板获得各自的正确层级。

真实桌面验收：在桌面放置一个普通应用窗口覆盖详情页出现区域，点击三个 Provider 图标，确认详情页均显示在普通窗口上方；再确认点击空白区域可关闭详情页，浮动条自身仍不覆盖普通应用窗口。
