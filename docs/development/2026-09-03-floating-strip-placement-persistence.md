# 浮动条位置稳定持久化开发日志

**需求：** `REQ-20260903-009`
**日期：** 2026-09-03
**平台：** macOS、Windows

## 背景与目标

用户把浮动条放在左侧或指定显示器后，重启、休眠唤醒、显示器重新连接或运行一段时间可能回到右侧，亦可能从主屏漂移到副屏。本次目标是持久保存具体物理显示器、左右侧与归一化垂直位置；多屏变单屏时只临时回到当前主屏，不覆盖原目标，目标屏恢复后自动回去。

正式规则见[设计规格](../design/specifications/2026-09-03-floating-strip-placement-persistence-design.md)，执行步骤见[实施计划](../design/implementation-plans/2026-09-03-floating-strip-placement-persistence.md)。

## 根因证据

现场偏好仍保存 `Automatic + Left + 约 48% + 数字显示器编号`，证明用户拖动保存链路本身有效。问题集中在恢复路径：

- macOS 把会随重启、唤醒和拓扑变化而变化的 `NSScreenNumber` 当作长期身份；
- 保存编号暂时找不到时，普通重排会生成“当前主屏 + 右侧 + 50%”并写回偏好；
- 一次短暂的显示器枚举缺失因此永久覆盖用户位置；
- 没有命中保存目标时，面板当前所在屏幕也可能影响选择，从而产生主副屏漂移。

Windows 已用原子 JSON 设置保存 `edge`、`meterVerticalPerMille`、`meterMonitorId`，但旧实现把会重编号的运行时显示器名称或几何信息写入 `meterMonitorId`，也没有运行中拓扑监听；目标屏缺失分支原本不会写回配置，本次保留并用合同测试锁定该语义。

## 实现与关键决定

### macOS 稳定身份

- 通过 Core Graphics display UUID 生成带 `uuid:` 命名空间的稳定标识；
- 保留旧 `NSScreenNumber` 作为一次性迁移线索，UUID 暂不可用时使用 `legacy:` 命名空间避免格式混淆；
- 主屏判断比较 display ID，不依赖 `NSScreen` 对象实例身份；
- 老版本裸数字或 `legacy:` 配置命中当前屏幕后，只迁移显示器标识，不修改侧边、垂直位置或模式。

### 目标优先与无损回退

- 已保存稳定目标在线时始终选择该物理显示器，不受当前主屏、屏幕枚举顺序或面板旧 frame 影响；
- 目标缺失时选择当前主屏，沿用保存侧边和相对高度；主屏不可用才选择第一块屏幕；
- 临时回退只改变现场 frame，启动、显隐、Space 切换和屏幕参数通知都不写入位置；
- 原目标重新出现后，下次系统重排会再次命中保存 UUID；
- 只有用户拖动、Settings/辅助功能明确移动以及无损旧标识迁移可以写位置。

### Windows 同步

- 用 Win32 设备接口路径识别物理显示器，规范化后只保存 SHA-256 哈希；配置不会暴露显示器名称、序列信息或原始设备路径；
- 旧版 `\\.\DISPLAYn` 运行时名称仍可命中同一显示器，并在带旧值守卫的条件下只迁移标识；接口查询不可用时使用同样经过哈希的运行时身份安全降级；
- 新增运行时拓扑监听，显示器连接、断开、主屏角色或工作区变化后按保存目标重新解析；目标缺失时临时回当前主屏，重新接入后自动恢复；
- 用户拖动或在 Settings 主动改变贴边侧时，把当前屏建立为新目标；系统触发的临时回退不会写回。

### 审查补强

首轮独立审查没有 Critical，但发现三项 Important：macOS Settings 改边未绑定当前屏；Windows 缺少运行中拓扑监听；Windows 旧名称不是稳定物理身份。三项均以失败先行测试复现，并按上述策略修复。计划中的组合测试筛选也改为逐测试类型执行，避免命令示例因显示名称不匹配而实际漏测。

二次审查又识别三个瞬时失败边界并阻止了过早合并：设备接口短暂不可用时保存的 `runtime:` 哈希现在会作为迁移别名，接口恢复后可升级为 `device:`；旧标识迁移先持久化候选副本，失败时保留旧内存配置且不阻断启动；拓扑监听初始枚举失败会继续轮询，定位失败前不提交新 topology，下一轮仍会重试。测试同时覆盖非主目标屏、主屏角色变化和工作区变化。

## 测试驱动证据

失败先行测试先要求尚不存在的稳定身份解析、迁移入口和位置持久化策略，确认旧实现无法满足新契约。随后用最小实现转绿，并补充两个边界：

- `legacy:<number>` 在 UUID 恢复后也能迁移；
- 临时回退必须同时保留 Left/Right 与精确归一化高度，而不仅仅是“不写配置”。

## 安全与隐私

- 新版本写入的配置只保存平台稳定标识和位置；Windows 原始设备路径会先哈希，升级前的旧运行时名称只会留在本机旧配置中并在目标重新出现时迁移，不采集账户或凭据；
- 文档和测试仅使用虚构的 `uuid:primary`、`secondary-display` 等标识；
- 未改变 Claude Code、OpenAI Codex、DeepSeek 的认证或数据读取边界。

## 本机与界面验收

自动化已覆盖全部状态转换。当前开发会话无法可靠控制第二块物理显示器的拔插、主屏角色切换和休眠唤醒，因此不会把策略测试冒充真实双屏验收。发布前仍应在可操作双屏环境依次验证：主屏/副屏分别摆放、重启、主屏角色切换、拔插、单屏回退和重新接入恢复。

## 已知限制

- 位置不会跨不同电脑同步；每台电脑维护自己的本地目标显示器。
- 若升级前的旧数字编号在多屏环境已无法唯一对应原设备，应用安全回退主屏，等待用户主动摆放；不会猜测某块副屏并覆盖配置。
- 物理显示器验收继续归入 `REQ-20260901-004` 的环境补验矩阵。
