# macOS PTY 并发分配稳定性修复

## 背景与目标

在 `0.2.0` 正式发布打包的完整回归中，`PTYCommandRunnerTests.concurrentCommandsPreserveOutput` 偶发返回 `transportFailure`。目标是在不牺牲 Claude Code、OpenAI Codex 与其他 CLI 命令并行执行能力的前提下，消除系统 PTY 分配阶段的竞争。

关联需求：`REQ-20260902-020`。

## 影响范围

- `PTYCommandRunner` 的 PTY 分配入口；
- 依赖 PTY 的 CLI 采集与认证命令；
- 完整测试和发布打包稳定性。

## 失败证据

- 32 路现有并发回归可复现 `.transportFailure`；
- 独立的 32、48、64 路 `openpty` 最小实验确认失败发生在系统分配调用本身，并非命令输出、超时或解析逻辑；
- 系统 PTY 上限和当前占用均未耗尽，排除常规资源上限原因。

## 实现与关键决定

为 `PTYCommandRunner` 增加进程内静态锁，只保护 `openpty` 的单次调用。文件描述符分配完成后立即释放锁；子进程启动、输出读取、超时、取消和退出等待均保持原有并发行为。

没有加入重试或延迟，因为这会掩盖系统调用竞争并增加不可预测等待；没有把整个命令执行过程串行化，以免降低刷新性能。

## 自动化验证

- 修复前：现有 32 路并发测试稳定复现失败；
- 修复后：聚焦回归连续通过；
- 完整回归：360 项测试、70 个测试组全部通过；
- 文档检查：118 份 Markdown 全部通过（新增本日志后为 119 份）；
- 公开发布安全检查通过。

## 本机与界面验收

本修复不改变界面。真实 CLI 行为继续由完整采集测试和发布包更新验收覆盖。

## 安全与隐私

不读取或记录命令环境、凭据、输出正文或用户路径；锁仅存在于当前应用进程内，不改变 Keychain、文件权限或网络行为。
