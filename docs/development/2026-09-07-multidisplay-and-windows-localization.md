# 2026-09-07：多显示器问题调查与 Windows 本地化需求

关联需求：`REQ-20260907-001`、`REQ-20260907-002`、`REQ-20260907-003`。本页记录调查与执行过程，不等同于真机验收或正式发布。

## 用户反馈与范围

- MacBook Pro M4 Max 接入主屏、副屏后，应用在副屏显示，不能拖到主屏；希望自由换屏、有屏幕选择，进一步考虑单屏或双屏同时显示。
- Windows 已安装成功，希望 English/简体中文选择，默认英文；新增微软雅黑、黑体、楷体，默认微软雅黑。macOS 不增加语言选择。
- 用户反馈没有提供当时 edge preference、已保存显示器身份或各屏坐标，不把本机源码分析写成异机完整复现。

## 多显示器代码证据

1. `Sources/AIMeterApp/System/FloatingPanelController.swift` 的 `updateStripDrag` 仅在 `.automatic` 时累加横向位移。固定 `.left/.right` 会忽略横向拖动，`endStripDrag` 又按浮动条中心选屏。因此左右排列屏幕在固定侧边时无法靠横拖切换，这是确定的实现限制。
2. `identity(for:)` 把 `NSScreen.main` 传入 `FloatingStripScreenIdentifier.identity` 作为主屏。Apple 定义该值为键盘焦点窗口所在屏幕，不保证为用户设置的系统主屏。系统主屏对应实时 `NSScreen.screens` 的首项。保存目标缺失或初次启动时，现有 resolver 会依据这个错误的 `isMain` 值回退。
3. 已保存且仍在线的 UUID 目标会优先于主屏。不能简单地每次强制回主屏，否则会破坏用户明确选择副屏的偏好。
4. 当前按窗口中心和 `visibleFrame` 命中屏幕，未直接按拖动指针所在的完整屏幕边界选目标。菜单栏、Dock、错位排列与跨屏边界需纳入回归；事件坐标转换、拖动期间重排是否干扰需进一步用测试验证，当前不宣称它们已被证实为根因。
5. `AppDelegate` 只持有一个 `FloatingPanelController`；每个控制器各拥有一个浮动条和一个详情，并直接占用 `model.floatingAppearanceHandler`。简单复制控制器会覆盖共享回调，不能直接用循环创建窗口实现所有显示器模式。

Apple 一手依据：[NSScreen.main](https://developer.apple.com/documentation/AppKit/NSScreen/main)、[NSScreen.screens](https://developer.apple.com/documentation/AppKit/NSScreen/screens)。旧位置持久化规格把 `NSScreen.main` 当成主屏的条款应由下一份修复规格明确取代，不删除历史记录。

## 推荐与备选

- **推荐：自由跨屏拖动 + 屏幕选择 + 可选所有显示器。** 新安装默认仅系统主屏；升级保留已选目标。固定左右侧边只控制松手后的吸附，不锁死换屏。Settings 提供系统主屏、指定屏幕、所有显示器；指定屏幕列表显示名称、内置/外置与主屏标记，并提供“移到主屏”快捷操作。
- **较小范围：本轮只做自由拖动和单屏选择。** 更快解决当前阻塞，保留单个控制器；所有显示器另一期开发。代价是无法同时在两屏看到浮动条。
- **不推荐：只增加主屏按钮或只清除保存位置。** 能暂时挪回主屏，但不解决拖动与主屏语义，也无法可靠保留用户选择。

所有显示器涉及新的窗口协调层，因此作为本次唯一需要确认的架构范围。建议具体约束：

- 数据采集、CLI、缓存和通知只有一份；多屏只增加展示窗口，不增加 API 请求。
- 每屏独立保存边缘与垂直位置，共享密度、字体、Provider 顺序；不复制敏感凭据。
- 同时最多一个详情/官网登录流程；点击另一屏时关闭旧详情，将详情归属移到点击屏，避免 WebView 多宿主。
- 所有屏模式中每个实例留在所属屏，可独立上下拖动/吸附；跨屏迁移用于单屏模式，避免拖出重复实例。界面提示清楚区分。
- 单屏指定目标离线时临时回系统主屏，不覆盖原目标；重新接入后恢复。所有屏模式按在线屏增删实例，镜像屏不重复生成；无屏时等待，不写默认位置。
- 拖动中暂停自动定位；松手后选目标屏再吸附，拓扑变化时安全取消/重新解析。正负坐标、左右/上下排列、缩放、休眠与断连均需覆盖。
- 跨平台共享位置语义保持一致；Windows 对等屏幕控制按正式规格纳入实施，不因本次仅 Mac 报错而悄悄造成长期功能分叉。

## Windows 本地化实施边界建议

- Settings → Appearance 增加 Language：English / 简体中文；默认 English，保存后即时生效，不要求重启应用。
- 翻译本应用的 Settings、详情、托盘/右键菜单、状态、通知与自有错误提示；服务名称保持 Claude Code、OpenAI Codex、DeepSeek。官方 CLI、DeepSeek 官网页面与操作系统原生弹窗不强行翻译。
- 不只替换前端静态文本：`windows/src-tauri/src/platform/windows/tray.rs`、`lib.rs` 的原生菜单及通知也有英文，需共享可测试的语言键和参数格式。数值、日期、复数与无障碍标签同步处理；不解析翻译后的文字作为业务协议。
- 字体保留旧选项，追加 Microsoft YaHei（微软雅黑）、SimHei（黑体）、KaiTi（楷体）；新安装和“恢复默认字体”使用微软雅黑。升级保留用户已有字体选择，不静默覆盖。
- 字体使用系统已安装版本，不打包或下载字体；缺失时明确标注不可用并回退微软雅黑/系统 sans-serif，不能出现无字或白色不可读下拉。
- 延续既有 Settings 零例外规则：Settings 文字随语言切换，但字号/字体仍固定平台系统样式；显示字体只影响浮动条、详情与应用内面板，原生菜单字体由系统控制。macOS 不增加语言选择、不改变字体默认值。
- 本地化配置缺失/未知值回退英文，不重置账户、位置、Key 或其他偏好。新旧偏好迁移、语言切换事件、实际中文布局与 Windows 多 DPI 都需测试。

### macOS 首轮复审

实现检查点：3b6dcee。独立复审发现并验证三项：

1. 断屏回退后主动改边/无障碍移动的读写目标不一致：实际 AppKit 回归在独立偏好中复现 selectedIdentifier 仍为离线屏；修复为主动操作选择当前借用屏并保留离线记录。
2. 新建/重连屏幕直接用保存边缘而忽略固定 Left/Right：统一位置解析应用固定约束；Automatic 才恢复各屏原边缘，不改写它们。
3. 旧 resolver 对不匹配数字 ID 的单屏迁移推测会覆盖离线目标：原测试修改为无损回退断言并先失败，再移除推测分支，只允许实际匹配迁移。

47 项定向回归及合同/文档/安全门禁通过，其中真实 AppKit 回退测试需 AI_METER_SCREEN_TESTS=1 与 WindowServer 权限；无屏 CI 默认跳过该 GUI 测试，其他纯策略测试照常运行。此测试只有一个真实当前屏，不代表双屏物理拔插验收。
