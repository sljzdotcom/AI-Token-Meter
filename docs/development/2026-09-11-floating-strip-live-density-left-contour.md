# 悬浮条密度即时生效与方案 B 轮廓修正

关联需求：REQ-20260911-013、REQ-20260911-014、REQ-20260911-015。日期：2026-09-11。

## 结果

双平台展开悬浮条采用用户确认的方案 B。Mini 以 65pt/px 为标准宽度，顶部轮廓从 `(65,4)` 开始，经三段连续 Bézier 曲线在 70pt/px 深度接入贴屏竖边；底部按高度严格垂直镜像，左贴边按宽度严格水平镜像。Compact 只按 78/65 横向缩放，Comfortable 使用 108pt/px 宽度与 88pt/px 肩深。

这组连续切线让左贴边时暴露侧右上角和右下角保持圆润，同时把贴屏侧反向肩弧延展到可辨认的 30pt/px 区域。三档密度、1至4个Provider、左右贴边及收起状态继续使用原有内容尺寸和命中语义。

## 密度即时生效

macOS 原有设置链是同步的：偏好保存后立即调用浮动面板外观更新。本轮增加原生 `NSPanel` frame 回归，确认已展开的 Compact 面板从 78pt 切到 Mini 后立即变为 65pt，并保持垂直中心和贴边位置。

Windows 的根因是设置已保存并立即广播，而原生窗口尺寸由后台显示器协调线程稍后更新，前端会先渲染新密度，窗口仍保留旧尺寸。现在协调队列为每一轮原生工作返回完成回执；设置命令等对应窗口调整完成后才发布最新设置。连续快速切换时，旧命令不会发布过期状态，后到请求只在自己所属的下一轮原生工作完成后返回。

## 验证证据

- TDD 红灯分别证明 Swift 缺少方案 B 几何、Windows 前端缺少共享路径生成器、Rust 仍使用旧关键点，以及原生协调队列没有完成回执；实现后对应专项全部转绿。
- macOS 方案 B、渲染、拖动与圆环包含专项 33 项通过；普通设置同步测试与受 `AI_METER_SCREEN_TESTS=1` 控制的真实 `NSPanel` 78→65pt 即时 frame 回归通过。
- Windows 前端完整 137 项通过；真实 Chrome 密度门禁覆盖 25 项生命周期、24 组展开布局、2 组收起布局、8 种 Antigravity 详情状态和 608 个文字角色。
- Windows Rust 完整测试通过，其中显示器协调专项 14 项、窗口策略专项 16 项；`cargo fmt --check` 与严格 Clippy 通过。
- `scripts/test.sh`、6份跨平台合同、可移植性与公开安全检查通过；文档校验覆盖 281 份 Markdown，`git diff --check` 通过。
- 独立初审报告Critical/Important/Minor为0/3/2，指出旧设置事件可能越过新事件、拖拽跳过轮次会提前完成回执、失败/超时后界面与持久化值可能不一致、Rust辅助几何会随总高度缩短肩深，以及计划勾选提前。逐项补充失败测试后，设置发布改为在同一锁内检查并发送，Deferred回执保留到实际原生轮次，失败与1ms可控超时统一进入发布和重试路径，辅助几何显式接收固定肩深；最终复核为0/0/0。
