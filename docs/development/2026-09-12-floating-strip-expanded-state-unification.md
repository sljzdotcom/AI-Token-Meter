# 自动隐藏展开与常驻展开终态统一

关联需求：REQ-20260912-001。日期：2026-09-12。

## 结果

macOS开启自动隐藏后，悬停展开的悬浮条现在直接使用与关闭自动隐藏时相同的精确窗口尺寸、位置、内容布局和方案B圆润轮廓。Comfortable、Compact、Mini都不再从20×96pt收起窗口拉伸；视觉节奏仍保留隐藏内容后等待140ms收起，以及展开后等待180ms显示内容。

Settings切换密度会取消旧转换并立即按最新偏好布置可见窗口。自动隐藏展开在显示内容前还会再次读取最新密度并提交精确终态，因此转换途中选择Mini也会落到65pt宽度，无需等待下一次收起或重新悬停。

Windows的原生窗口协调本来就是直接提交目标尺寸，没有同类frame拉伸。本轮只扩展共享行为合同和前端回归，不修改Windows产品逻辑。

## 根因与失败证据

常驻展开和Settings外观更新直接调用`NSPanel.setFrame`，而自动隐藏展开走另一条`NSWindow` frame动画路径。非线性透明Shape随整个窗口从收起尺寸拉伸，在动画中和终点都可能保留尖锐的缩放/裁切观感。原有密度回归只读取未完整经历自动隐藏转换的面板外框，因此没有覆盖用户看到的路径。

TDD先加入真实可见`NSPanel`的三密度收起→展开回归，以及内容时序与窗口几何分离合同。修复前缺少转换计划和内容bounds终态钩子，专项失败；实现后每种密度都证明展开立即到达目标宽度、content bounds与窗口frame一致，等待淡入后frame不再变化。

## 实现

- `FloatingPanelController`的所有位置提交统一使用精确、无动画的`setFrame`；不再对透明异形窗口执行frame缩放。
- 新增纯数据转换计划，集中记录折叠140ms和展开180ms的内容可见性延迟；Reduce Motion时延迟为零。
- 收起先隐藏内容，延迟结束后提交20×96pt；展开先提交当前密度的完整窗口，延迟结束前再次提交最新密度，再显示内容。
- 拖拽期间收到的密度更新会暂存到松手时处理；拖拽吸附和暂存外观均以无动画精确frame提交，避免重入窗口缩放路径。
- 共享悬浮条行为合同声明展开窗口不做frame动画；Windows前端校验相同合同，维持现有直接原生尺寸提交。
